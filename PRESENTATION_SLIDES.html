Persistence Tier

Dedicated Database: Microsoft SQL Server (SSMS)

Strict relational integrity on AeroStoreDB with pyodbc connection management.

🗄️ Relational Schema: AeroStoreDB
  • users Table: PBKDF2 password hashes (100,000 rounds), salts, roles (admin, delivery, customer), VIP status.
  • products Table: SKUs, stock levels, pricing, category, specs JSON, ratings.
  • orders Table: Status (CONFIRMED, DISPATCHED, IN_TRANSIT, DELIVERED), subtotal, courier.
  • order_items Table: Foreign-key order items with quantities, prices, and line totals.
  • coupons Table: Discount percentages, active dates, and minimum order spend thresholds.
🛡️ Enterprise Database Governance
  • Atomic ACID Transactions: Governed by context managers with automatic rollback on exception.
  • Parameterized T-SQL Queries: Zero raw string interpolation; 100% immune to SQL injection.
  • Dedicated Connection Engine: Uses ODBC Driver 17/18 with health diagnostics (python run.py ssms).
  • Dual-Mode Thread-Safe Cache: Guarantees seamless offline simulation and fast automated testing.
High-Concurrency Engine

Flash-Sale Concurrency & Distributed Saga Resilience

Zero inventory overselling, sub-1500ms SLA guarantee, and automatic rollback.

1. Optimistic Concurrency Control (OCC)
  • Each cart carries an integer concurrency_version tag.
  • Prevents lost updates during simultaneous flash-sale updates.
  • Stale version tokens immediately reject with 409 Conflict.
  • Tested and verified under concurrent multi-threaded contention.
2. Inventory Reservation Locks
  • Phase 1 of checkout validates and reserves physical inventory.
  • Quantity limits (max 99) and negative checks strictly enforced.
  • Prevents overselling when stock drops to 0 during flash sales.
  • Real-time stock decrement across SSMS persistence.
3. 1500ms Payment SLA Limit
  • Strict SLA timeout enforced at the Payment Gateway service.
  • Timeouts exceeding 1500ms raise PaymentTimeoutException.
  • Returns 504 Gateway Timeout with RFC 7807 problem details.
  • Idempotency key deduplication prevents duplicate charges.
4. Saga Compensating Rollbacks
  • If payment settlement fails or times out, the saga rollback fires.
  • Reserved catalog inventory is automatically restored in full.
  • Financial ledger and physical stock remain 100% consistent.
  • Zero orphaned charges or reserved stock leakage.

Requirements Breakdown & Architecture Design

📝 Prompt Engineering Analysis
❌ Bad Prompt (Intent Only):

"Design an online shopping system."
Deficiencies: Ambiguous boundaries, no scale metrics (fails 10k users), non-deterministic text instead of JSON schema.

✔ Good Prompt (Context + Constraints + Schema):

"You are a senior architect. Design a microservices online shopping system. Constraints: 10k concurrent users, REST APIs only, contract-first design. Output in structured JSON with: services, responsibilities, API boundaries, risks."

🏛️ Architectural Deliverables & ADRs
  • architecture.json: Microservices decomposition: Catalog (read-heavy), Cart (OCC), Order (Saga), and Payment (SLA).
  • ADR-001 (Microservices Adoption): Decouples write-heavy transactions from read queries for 10k users.
  • ADR-002 (Non-AI in Payment Logic): Strict policy: Generative AI models are strictly prohibited from payment settlements.
  • Token Budget Matrix: T=0.0 for code/contracts; T=0.2 for RAG facts; T=0.7 for creative marketing.
